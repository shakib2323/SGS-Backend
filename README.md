# SGS backend

Spring Boot 3 / Java 21 / MySQL 8 backend for the Super Glazing System website and the employee bank.
Replaces Firebase. Frontend stays static (GitHub Pages) and talks to this API.

## Run locally
```bash
docker run -d --name sgs-mysql -e MYSQL_ROOT_PASSWORD=root -e MYSQL_DATABASE=sgs -p 3306:3306 mysql:8.4
mvn spring-boot:run -Dspring-boot.run.profiles=dev
# first admin (dev profile): admin / ChangeMe!12345  -> you must change it at first login
```
Uploads go to `./uploads` and are served at `http://localhost:8080/files/...` in dev.

## Tests
`mvn verify` runs the unit tests (image pipeline incl. EXIF rotation, URL validation, rate limiter, password rules).

## Deploy (VPS + Docker + Caddy + GitHub Actions)
1. **Server (Ubuntu 22.04/24.04)**: install Docker + compose plugin, create `/opt/sgs`, copy `.env.example` -> `/opt/sgs/.env` and fill it (`chmod 600`).
   Add a 2 GB swap file if the VPS has 1 GB RAM. SSH keys only, no root login. Run `deploy/cloudflare-ufw.sh` once.
2. **DNS (Cloudflare)**: `api` A record -> VPS IP (proxied), `www` -> GitHub Pages. SSL mode **Full (strict)**.
3. **GitHub repo secrets** (Settings -> Secrets -> Actions): `VPS_HOST`, `VPS_USER`, `VPS_SSH_KEY`, `GHCR_READ_TOKEN` (classic PAT with `read:packages`).
   Create an Environment named `production` (optional approval gate).
4. Push to `main` -> tests -> image to GHCR -> compose/Caddyfile copied -> `docker compose pull && up -d`.
5. Cron the backup: `0 2 * * * /opt/sgs/deploy/backup.sh` and copy `/opt/sgs/backups` off the server (rclone).
6. After first login remove `ADMIN_USERNAME/ADMIN_PASSWORD` from `.env`.

## Decisions and assumptions (change if you disagree)
- **Gallery/project categories**: Residential, Commercial, High Corporate, Industrial, Other. Industrial is my pick for "one more"; admin can rename/add/disable categories at runtime.
- **Bank immutability**: employees can only add and view. - **Permanent suspension**: the employee cannot log in, so cannot see anything; admin still sees and manages all bank records of that employee.
- **Temporary suspension** ends by itself; admin can lift any suspension at any time. Suspending signs the employee out immediately.
- **Upload permission** is gallery-only and time-limited (hours or until a date); admin can withdraw it at any time.
- **Employee passwords**: generated by admin (or chosen), user must change at first login; admin reset requires the username.
- **Images** are decoded, EXIF-rotated, resized (max 1600 px, thumb 480 px) and re-encoded to JPEG/PNG, which strips metadata and hidden payloads. Uploads: JPG, PNG, WebP, GIF, 6 MB max.
- **Extras added**: audit log, dashboard counts, visitor inquiries (honeypot + Turnstile + rate limit), service SEO fields/features/warranty/price note, project status/area/featured, display ordering, nightly backup script.

## Security model in one paragraph
JWT in an HttpOnly, Secure, SameSite=Strict cookie; user state is re-read from MySQL on every request (suspension and resets are instant);
CSRF defended by SameSite + mandatory `X-Requested-With` header + CORS allow-list; BCrypt(12); login throttling; URL fields accept only http(s);
uploads are re-encoded; all SQL via JPA/parameters; API container and MySQL are not exposed to the internet; origin firewalled to Cloudflare.
